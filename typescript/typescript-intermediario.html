Trilha TypeScript

Nível Intermediário: Modelagem de Negócio e POO

O desenvolvedor júnior aprende a estruturar serviços, DTOs de APIs, repositórios e classes com contratos rigorosos.

O que você domina neste nível?

Depois dos fundamentos, TypeScript passa a proteger decisões de arquitetura: entidades, estados de negócio, coleções, classes, módulos e respostas de API.

1. interface versus type

Interfaces são excelentes para formatos de objetos e contratos que podem ser estendidos ou implementados por classes. Aliases são mais flexíveis para unions, literais, tuplas e combinações.

type StatusPedido = "PENDENTE" | "PAGO" | "CANCELADO";

interface Pedido {
  id: number;
  total: number;
  status: StatusPedido;
  clienteEmail?: string;
  readonly criadoEm: Date;
}

const pedido: Pedido = {
  id: 1,
  total: 500,
  status: "PENDENTE",
  criadoEm: new Date()
};

Use unions literais para restringir estados. Use propriedades opcionais somente quando a ausência for realmente válida.

2. Coleções tipadas e tuplas

Pedido[] e Array<Pedido> garantem que métodos como map, filter e find conheçam os campos dos itens.

const pedidos: Pedido[] = [pedido];
const totais: Array<number> = pedidos.map((item) => item.total);
const pagos = pedidos.filter((item) => item.status === "PAGO");

const resposta: [number, string] = [200, "OK"];
const respostaRotulada: [status: number, corpo: string] = [200, "OK"];

Tuplas têm tamanho e posições conhecidas. Use-as para retornos pequenos e estruturados, não como substituto de objetos com nomes claros.

3. Orientação a objetos com modificadores

public é acessível em qualquer lugar; private somente dentro da classe; protected também permite acesso em subclasses. Encapsule regras para impedir mutações inválidas.

class ContaBancaria {
  public readonly titular: string;
  private saldo: number;

  constructor(titular: string, saldoInicial: number) {
    this.titular = titular;
    this.saldo = saldoInicial;
  }

  public depositar(valor: number): void {
    if (valor > 0) {
      this.saldo += valor;
    }
  }

  public getSaldo(): number {
    return this.saldo;
  }
}

readonly impede reatribuir o titular depois da inicialização, enquanto o saldo só muda por métodos autorizados.

4. Generics básicos

Generics aceitam tipos diferentes sem recorrer a any e preservam a relação entre entrada e saída.

interface RespostaApi<T> {
  sucesso: boolean;
  dados: T;
}

type Usuario = {
  id: number;
  nome: string;
};

const respostaUsuario: RespostaApi<Usuario> = {
  sucesso: true,
  dados: { id: 1, nome: "Nicolas" }
};

O mesmo contrato pode servir para usuários, contas, transações e qualquer entidade sem perder os campos específicos de cada dado.
