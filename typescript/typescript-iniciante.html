Trilha TypeScript

Guia Definitivo: TypeScript para Back-End (Do Zero ao Avançado)

Primeiro nível: o compilador, os tipos fundamentais e a diferença entre proteção de desenvolvimento e execução.

Regra de ouro: TypeScript é uma armadura de análise estática. O código final é transpilado para JavaScript antes de rodar no Node.js.

Visão geral dos níveis

No nível iniciante, você domina o compilador, tipos primitivos, inferência, any, unknown e contratos simples com interface. Depois, a trilha avança para modelagem de negócio e engenharia de tipos.

1.1 O compilador e o tsconfig.json

O TypeScript não é executado diretamente pelo Node.js tradicional. O tsc verifica os tipos e remove as anotações, gerando arquivos JavaScript comuns.

{
  "compilerOptions": {
    "strict": true,
    "target": "ES2022",
    "rootDir": "src",
    "outDir": "dist"
  },
  "include": ["src"]
}
  • strict ativa verificações rigorosas.
  • target define a versão de JavaScript gerada.
  • rootDir indica os fontes e outDir a saída compilada.
npx tsc --noEmit
npx tsc
node dist/index.js

1.2 Tipos primitivos e inferência

Use os tipos em letras minúsculas: string, number e boolean. TypeScript não possui tipos separados para int e float; ambos pertencem a number.

let nome: string = "Nicolas";
let idade = 20; // O compilador infere number.
const ativo: boolean = true;

// idade = "vinte"; // Erro: string não pode substituir number.

function dobro(valor: number): number {
  return valor * 2;
}

Inferência reduz repetição, mas anotações são úteis em APIs públicas, parâmetros importantes e fronteiras de dados.

1.3 Tipos especiais: fuja do any

any desliga a checagem. unknown é seguro porque exige verificação antes do uso. void indica que uma função não devolve um valor útil; never indica que ela nunca chega ao final normalmente.

let legado: any = "sem proteção";
const entrada: unknown = "dado externo";

function registrar(): void {
  console.log("Ação concluída");
}

function falhar(mensagem: string): never {
  throw new Error(mensagem);
}

Em aplicações profissionais, prefira unknown para respostas de API, arquivos e valores recebidos do usuário. A validação de runtime será estudada no nível avançado.
