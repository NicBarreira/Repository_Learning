Nível Avançado: Engenharia de Tipos e Infraestrutura

Utility Types, narrowing, conditional types, tipos mapeados e validação de runtime para bibliotecas e serviços rigorosos.

O que caracteriza o nível avançado?

O TypeScript atua no compile-time, mas dados de requisições continuam podendo estar errados no runtime. Engenharia de tipos combina precisão estática, APIs expressivas e validação real na entrada do sistema.

1. Utility Types nativos

Utility Types transformam modelos existentes sem duplicar contratos. Eles são úteis para DTOs de criação, atualização, respostas públicas e mapas.

interface UsuarioCompleto {
  id: number;
  nome: string;
  email: string;
  senhaHash: string;
}

type UsuarioAtualizacao = Partial<UsuarioCompleto>;
type UsuarioPublico = Omit<UsuarioCompleto, "senhaHash">;
type UsuarioIdentidade = Pick<UsuarioCompleto, "id" | "nome">;
type UsuariosPorId = Record<string, UsuarioPublico>;
  • Partial<T> torna propriedades opcionais.
  • Pick<T, K> seleciona campos.
  • Omit<T, K> remove campos sensíveis.
  • Record<K, T> cria um mapa tipado.

2. Type Narrowing e Type Guards

Narrowing afunila um tipo amplo durante a execução. Os operadores nativos incluem typeof, instanceof e in. Um custom type guard usa a forma valor is Tipo.

function ehString(valor: unknown): valor is string {
  return typeof valor === "string";
}

function formatar(valor: unknown): string {
  if (ehString(valor)) {
    return valor.toUpperCase();
  }

  if (typeof valor === "number") {
    return valor.toFixed(2);
  }

  return "Valor não suportado";
}

A função de guarda executa uma verificação real e comunica o resultado ao compilador. Ela não deve apenas fingir que um valor é seguro.

3. Conditional Types e infer

Conditional Types tomam decisões estáticas no formato T extends U ? X : Y. infer captura uma parte de uma estrutura, como o retorno de uma função ou o valor de uma Promise.

type Retorno<T> =
  T extends (...args: never[]) => infer R ? R : never;

type ValorDaPromise<T> =
  T extends Promise<infer V> ? V : T;

type Resposta<T> =
  T extends string
    ? { tipo: "texto"; valor: T }
    : { tipo: "outro"; valor: T };

Essas ferramentas permitem extrair metadados de APIs genéricas, compor contratos e criar utilitários reutilizáveis. Use tipos auxiliares nomeados para não transformar cada assinatura em uma expressão impossível de manter.

4. Validação em runtime: TypeScript com Zod

Os tipos desaparecem quando o JavaScript roda. Dados de req.body, arquivos e APIs precisam ser validados no runtime. O Zod permite declarar um schema executável e inferir o tipo correspondente.

import { z } from "zod";

const usuarioSchema = z.object({
  nome: z.string().min(3),
  idade: z.number().int().positive()
});

type UsuarioInput = z.infer<typeof usuarioSchema>;

function validarUsuario(valor: unknown): UsuarioInput {
  return usuarioSchema.parse(valor);
}

parse lança erro quando os dados são inválidos; safeParse devolve um resultado que pode ser tratado sem exceção. A validação deve ocorrer antes de dados externos entrarem nas regras de negócio.

Regra de segurança: TypeScript não substitui autenticação, autorização, sanitização, logs ou validação financeira. Tipos e runtime cumprem funções diferentes.
