Trilha Node.js

Nível Avançado: Arquitetura, Performance e Baixo Nível

Como o runtime agenda trabalho, processa grandes volumes, distribui carga e protege APIs em produção.

O que caracteriza a engenharia de servidores?

O objetivo não é apenas fazer uma rota responder, mas manter latência previsível, consumo de memória controlado, concorrência segura e proteção contra falhas em lote.

1. Event Loop e libuv

O Node.js executa JavaScript em uma thread principal e delega I/O de rede e disco à libuv. Microtasks como Promises e process.nextTick têm prioridade antes dos timers e do polling de I/O.

console.log("1: síncrono");

setTimeout(() => console.log("4: timer"), 0);
Promise.resolve().then(() => console.log("3: microtask"));
process.nextTick(() => console.log("2: nextTick"));

console.log("1: fim do síncrono");

A ordem exata deve ser considerada ao diagnosticar latência: o código síncrono termina, as filas prioritárias são esvaziadas e só depois os timers avançam.

2. Buffers e Streams

Buffer representa bytes brutos fora da memória comum de objetos V8. Streams transferem dados em chunks e evitam carregar um arquivo de 1 GB inteiro na RAM.

import { createReadStream, createWriteStream } from "node:fs";

const origem = createReadStream("relatorio.csv");
const destino = createWriteStream("relatorio-copia.csv");

origem.on("error", console.error);
destino.on("error", console.error);
origem.pipe(destino);
destino.on("finish", () => console.log("Cópia concluída."));

O pipe conecta leitura e escrita, respeitando backpressure quando o destino não consegue acompanhar a origem.

3. Multiprocessamento: Cluster e Worker Threads

O módulo cluster cria processos filhos que podem dividir requisições entre núcleos. worker_threads executa cálculos pesados sem congelar as rotas HTTP.

import cluster from "node:cluster";
import { availableParallelism } from "node:os";

if (cluster.isPrimary) {
  const quantidade = availableParallelism();
  for (let i = 0; i < quantidade; i += 1) cluster.fork();
} else {
  iniciarServidor();
}

Use workers para CPU intenso, como redimensionamento de imagens ou criptografia. Não use múltiplos processos como substituto para corrigir vazamentos de memória.

4. Segurança e autenticação

  • Faça hashing unidirecional de senhas com bcrypt ou argon2; nunca armazene a senha original.
  • Emita JWTs com expiração curta, valide assinatura e não confie apenas no conteúdo decodificado.
  • Separe autenticação de autorização e aplique RBAC para controlar permissões.
  • Valide entradas, limite requisições, oculte segredos e registre falhas sem expor dados sensíveis.
Regra de produção: performance não compensa uma API que aceita dados inválidos ou permite acesso sem autorização.
