1. O motor interno: Call Stack, Heap e Garbage Collection

Node.js e navegadores usam o motor V8. A Call Stack executa funções de forma síncrona no modelo LIFO: a última chamada adicionada é a primeira a terminar.

O Memory Heap armazena objetos, arrays e closures. O Garbage Collector usa técnicas como Mark-and-Sweep para liberar estruturas que não possuem mais referências alcançáveis.

function criarSessao() {
  const sessao = { usuarioId: "u1" };
  return sessao;
}

let sessaoAtual = criarSessao();
sessaoAtual = null; // A sessão anterior pode ser coletada futuramente.

Memory leaks acontecem quando referências continuam ativas sem necessidade, como listeners nunca removidos, caches infinitos e variáveis globais acumuladas.

2. A ordem do Event Loop: Microtasks e Macrotasks

JavaScript executa o código principal em uma thread, mas o ambiente coordena operações externas. Primeiro a Call Stack precisa esvaziar; depois as microtasks são processadas; só então macrotasks aguardam sua vez.

Prioridade prática

  • Call Stack: código síncrono, como condições e console.log.
  • Microtasks: callbacks de Promises e queueMicrotask.
  • Macrotasks: timers, eventos e tarefas agendadas pelo ambiente.
console.log("1: síncrono");

setTimeout(() => console.log("4: macrotask"), 0);

Promise.resolve().then(() => {
  console.log("3: microtask");
});

console.log("2: síncrono");

// Ordem: 1, 2, 3, 4.

Uma cadeia infinita de microtasks pode atrasar timers e eventos. Por isso, tarefas pesadas devem ser divididas ou movidas para workers/processos adequados.

3. Metaprogramação: Proxy e Reflect

Metaprogramação permite interceptar operações básicas, como leitura e escrita de propriedades. Proxy cria uma camada de interceptação; Reflect executa a operação padrão de forma consistente.

const conta = { saldo: 100 };

const contaVigiada = new Proxy(conta, {
  set(alvo, propriedade, valor) {
    if (propriedade === "saldo" && valor < 0) {
      throw new Error("Saldo não pode ficar negativo");
    }

    return Reflect.set(alvo, propriedade, valor);
  }
});

contaVigiada.saldo = 500;

Proxies são úteis em validação e reatividade, mas aumentam a complexidade. Use-os quando a interceptação realmente fizer parte do modelo da aplicação.

4. Controle de fluxo sob demanda: Generators

Uma função geradora usa function* e pode pausar com yield. Cada chamada de next() continua de onde a execução parou.

function* gerarContador() {
  let id = 1;

  while (true) {
    yield id;
    id += 1;
  }
}

const contador = gerarContador();
console.log(contador.next().value); // 1
console.log(contador.next().value); // 2

Generators permitem lazy evaluation: valores são produzidos sob demanda, sem carregar uma sequência inteira na memória.

5. Baixo nível no backend: Buffers e Streams

Buffers representam sequências brutas de bytes. Streams processam dados em pequenos chunks, evitando carregar um arquivo ou upload inteiro na RAM.

import { createReadStream, createWriteStream } from "node:fs";

const origem = createReadStream("./entrada.csv");
const destino = createWriteStream("./copia.csv");

origem.pipe(destino);

destino.on("finish", () => {
  console.log("Arquivo copiado por partes");
});

pipe conecta uma stream de leitura a uma stream de escrita. Em aplicações reais, trate erros, backpressure e encerramento dos recursos.

const dados = Buffer.from("transferência");
console.log(dados);
console.log(dados.toString("utf8"));
