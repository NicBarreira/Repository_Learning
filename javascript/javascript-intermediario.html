Guia de JavaScript Intermediário

Foco em backend, TypeScript, modularização, APIs REST, regras financeiras e organização de sistemas reais.

1. O que muda do básico para o intermediário?

O iniciante aprende comandos, variáveis, comparações, laços e funções. O intermediário aprende a organizar sistemas, separar arquivos, tratar dados e conversar com APIs e bancos sem travar a aplicação.

const trilha = {
  iniciante: "comandos e lógica básica",
  intermediario: "módulos, dados e regras de negócio",
  avancado: "runtime, performance e baixo nível"
};

console.log(trilha.intermediario);

O resultado esperado é sair de scripts isolados para aplicações divididas em camadas e responsabilidades.

2. Modularização: dividir para conquistar

Em projetos reais, regras, infraestrutura e apresentação devem ficar em arquivos menores. export disponibiliza uma declaração e import reutiliza somente o que é necessário.

// conta.js
export function podeSacar(saldo, valor) {
  return valor > 0 && valor <= saldo;
}

// app.js
import { podeSacar } from "./conta.js";

console.log(podeSacar(500, 100));

Prefira ES Modules modernos, imports explícitos e módulos com responsabilidade única. Isso prepara o código para TypeScript e facilita os testes.

3. Métodos de listas: chega de laços manuais

Bancos de dados e APIs devolvem coleções o tempo todo. map transforma, filter filtra, find busca o primeiro item e reduce calcula um resultado único.

const despesas = [
  { categoria: "luz", valor: 120 },
  { categoria: "internet", valor: 80 },
  { categoria: "aluguel", valor: 900 }
];

const valores = despesas.map((despesa) => despesa.valor);
const grandes = despesas.filter((despesa) => despesa.valor > 100);
const internet = despesas.find((despesa) => despesa.categoria === "internet");
const total = despesas.reduce((soma, despesa) => soma + despesa.valor, 0);

Esses métodos evitam mutações acidentais e deixam explícita a intenção de cada transformação.

4. Assincronismo real: async, await e Promise.all

Consultas a banco, APIs externas e arquivos levam tempo. await pausa a função atual, mas não bloqueia o servidor inteiro. Promise.all executa tarefas independentes em paralelo.

async function carregarPainel(clienteId) {
  try {
    const [conta, transacoes] = await Promise.all([
      buscarConta(clienteId),
      buscarTransacoes(clienteId)
    ]);

    return { conta, transacoes };
  } catch (erro) {
    console.error("Falha ao carregar o painel:", erro);
    throw erro;
  }
}

Não use operações sequenciais quando uma resposta não depende da outra. Trate erros no ponto adequado e mantenha mensagens úteis para logs e usuários.

5. Boas práticas e orientação a objetos

Classes juntam dados e regras, como uma conta bancária com operações de depósito e saque. Encapsule invariantes para impedir estados inválidos.

class Conta {
  #saldo = 0;

  depositar(valor) {
    if (valor <= 0) return false;
    this.#saldo += valor;
    return true;
  }

  consultarSaldo() {
    return this.#saldo;
  }
}

const conta = new Conta();
conta.depositar(500);

Early return reduz aninhamento: valide erros no início e retorne imediatamente. Desestruturação torna os parâmetros e os dados lidos mais claros.

function criarTransferencia({ origem, destino, valor }) {
  if (valor <= 0) return { ok: false, erro: "Valor inválido" };
  return { ok: true, origem, destino, valor };
}

6. Como isso prepara você para TypeScript?

TypeScript coloca contratos sobre os mesmos pilares de JavaScript. Arrays passam a ser Task[] ou Account[]; objetos passam a exigir interfaces; Promises informam seu resultado com Promise<T>.

interface Conta {
  id: string;
  saldo: number;
}

async function buscarConta(id: string): Promise<Conta | null> {
  console.log(`Buscando ${id}`);
  return null;
}
